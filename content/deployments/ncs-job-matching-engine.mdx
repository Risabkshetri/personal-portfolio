## The constraint

Most job-matching engines assume a clean input: a structured résumé, a tagged
skills list, a job description written to a taxonomy. A national career-services
ecosystem does not look like that. Profiles are partial. Skills are free-text or
missing. The same role is described five different ways across five sources. Any
matching approach that needs tidy data fails silently on the majority of real
profiles. It returns weak matches and no one can tell why.

The actual problem was not "which model ranks jobs best." It was to **produce
useful matches and an honest skill-gap read from data that is sparse,
inconsistent, and entered by people who are not thinking about machine
readability.**

## What I built

- **Normalisation layer.** Free-text roles, skills, and qualifications are mapped
  to a canonical skill/occupation vocabulary before anything else runs. LLM-
  assisted extraction fills gaps where a profile has prose but no structured
  fields; deterministic rules handle the high-frequency cases so cost and latency
  stay predictable.
- **Matching.** Candidate and role are embedded into a shared vector space over
  the canonical vocabulary, then re-ranked with explicit features (location,
  seniority, hard requirements) so a strong semantic match can't override a
  disqualifying constraint.
- **Skill-gap model.** For a target role, the engine returns the specific skills
  a profile is missing, ranked by how much each one changes match quality. The
  output is "learn these three things," not a score.

## What broke

This is the section that matters.

- **Silent taxonomy drift.** Source data used role titles that mapped cleanly at
  integration time and then drifted. Matches degraded slowly rather than
  failing, so the problem was invisible until we started sampling low-confidence
  matches on a schedule. {/* TODO(rishab): keep or replace with the real failure. */}
- **LLM extraction over-confidence.** Early on, the extraction step would invent
  plausible structured skills from thin prose. The fix was to make it abstain
  (no field rather than a guessed field) and treat abstention as normal.
- **Cost and latency at the tail.** A small fraction of profiles were large and
  messy enough to blow the latency budget. Capping work per profile and degrading
  gracefully mattered more than optimising the median.
